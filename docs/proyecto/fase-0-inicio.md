# Fase 0. GitHub, Markdown y ficha inicial

[Guía de la práctica](practica.md) · **Al terminar:** README, ficha, bitácora y memoria iniciados.

**Sesión de clase:** 1. Consulta el [calendario](../clases/index.md).

Empieza por el repositorio: será el lugar donde explicarás lo que vas
construyendo y guardarás las pruebas de cada fase. Sigue la
[guía de la primera sesión](primera-sesion.md) si necesitas ayuda con GitHub
o con los primeros documentos en Markdown.

1. Crea tu repositorio individual en GitHub.
2. Publica `README.md`, `.gitignore`, `docs/00-ficha-inicial.md` y
   `docs/00-bitacora.md`, junto con la estructura inicial.
3. Inicia `docs/10-memoria-tecnica.md` con resumen, necesidad, objetivos
   comprobables, alcance e índice. Al terminar cada sesión, pasa de la bitácora
   a la memoria las decisiones, configuraciones y resultados ya depurados; no
   copies el diario completo. Se completará a lo largo del proyecto.
4. Comprueba los enlaces del README y el primer commit en GitHub.
5. Entrega la URL en Aules y verifica el acceso del profesor.

El profesor validará este hito inicial antes del trabajo sobre Proxmox.
Si falla la conexión o el acceso a la cuenta, registra la incidencia,
conserva el trabajo local y publica al recuperar el acceso; la incidencia
no elimina la obligación de alojar la documentación en GitHub.

Completa `docs/00-ficha-inicial.md` con:

| Campo | Contenido |
|---|---|
| Nombre del alumno | |
| URL del repositorio GitHub | |
| Entorno previsto | Proxmox en VirtualBox; instalación en equipo dedicado solo como opción autorizada |
| Equipo anfitrión y recursos de la VM si procede | CPU, RAM, disco, VirtualBox y red |
| Nombre del nodo | Ejemplo: `pve-apellido` |
| Servicio ASO elegido | Samba, NFS, SSH, LDAP, CUPS, Nginx administrado u otro |
| Red de laboratorio | Subred, gateway, DNS y VLAN si procede |
| Riesgos iniciales | Recursos limitados, virtualización anidada, disco, red |
